# Amazon S3

## What Is S3?

Simple Storage Service (S3) provides object storage with 99.999999999% (11 nines) durability. You store data as objects inside buckets.

## Buckets and Objects

- **Bucket**: A globally unique container. Must have a DNS-compliant name.
- **Object**: A file + metadata + version ID. Max size: 5 TB.

```bash
# Create a bucket
aws s3 mb s3://my-unique-bucket-name --region us-east-1

# Upload an object
aws s3 cp data.csv s3://my-unique-bucket-name/data.csv

# List objects
aws s3 ls s3://my-unique-bucket-name/
```

## Storage Classes

| Class | Use Case | Retrieval |
|-------|----------|-----------|
| S3 Standard | Frequent access | Instant |
| Standard-IA | Infrequent but rapid | Instant (per-GB retrieval fee) |
| One Zone-IA | Reconstructable data | Instant, single AZ |
| Glacier Instant | Archive, millisecond | Instant |
| Glacier Flexible | Archive, minutes–hours | Minutes to hours |
| Glacier Deep Archive | Long-term archive | Hours |
| Intelligent-Tiering | Unknown/variable patterns | Automatic |

## Versioning

Versioning preserves, retrieves, and restores every version of an object.

```bash
aws s3api put-bucket-versioning \
  --bucket my-unique-bucket-name \
  --versioning-configuration Status=Enabled
```

- Protects against accidental deletes
- Enables rollbacks to any previous version
- MFA Delete adds additional protection

## Lifecycle Policies

Automatically transition or expire objects based on age.

```json
{
  "Rules": [
    {
      "ID": "MoveToIA",
      "Status": "Enabled",
      "Transitions": [
        { "Days": 30, "StorageClass": "STANDARD_IA" },
        { "Days": 90, "StorageClass": "GLACIER" }
      ],
      "Expiration": { "Days": 365 }
    }
  ]
}
```

```bash
aws s3api put-bucket-lifecycle-configuration \
  --bucket my-unique-bucket-name \
  --lifecycle-configuration file://lifecycle.json
```

## Static Website Hosting

```bash
# Enable website hosting
aws s3api put-bucket-website \
  --bucket my-static-site \
  --website-configuration '{
    "IndexDocument": { "Suffix": "index.html" },
    "ErrorDocument": { "Key": "error.html" }
  }'
```

Bucket policy for public access:

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": "*",
    "Action": "s3:GetObject",
    "Resource": "arn:aws:s3:::my-static-site/*"
  }]
}
```

Website endpoint: `http://my-static-site.s3-website-us-east-1.amazonaws.com`

## Pre-Signed URLs

Generate temporary URLs that grant time-limited access to private objects.

```python
import boto3

s3 = boto3.client('s3')
url = s3.generate_presigned_url(
    'get_object',
    Params={'Bucket': 'my-bucket', 'Key': 'report.pdf'},
    ExpiresIn=3600  # 1 hour
)
print(url)
```

## Server Access Logging

Logs all access requests to a bucket. Useful for security auditing and compliance.

```bash
# Enable logging — logs go to another bucket
aws s3api put-bucket-logging \
  --bucket my-unique-bucket-name \
  --bucket-logging-status '{
    "LoggingEnabled": {
      "TargetBucket": "my-logs-bucket",
      "TargetPrefix": "s3-access-logs/"
    }
  }'
```

## Interview Q&A

**Q1: What is the difference between SSE-S3, SSE-KMS, and SSE-C encryption?**
SSE-S3 uses AES-256 encryption managed entirely by S3 with automatic key rotation. SSE-KMS uses AWS KMS for key management, providing an audit trail and key policy control. SSE-C (customer-provided) lets you supply your own encryption key with each request — AWS stores only the encrypted data but not the key.

**Q2: How would you design a lifecycle policy for a data lake?**
A typical pattern: move new objects to S3 Standard for 30 days of frequent access, transition to S3 Standard-IA for 30–90 days, move to Glacier Flexible for 90–365 days, and expire after 365 days. Use S3 Intelligent-Tiering for objects with unpredictable access patterns. Enable versioning on the bucket and set non-current version expiration to clean up old versions after 90 days.
