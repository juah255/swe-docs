# Resources

Shared reference material, links, and supporting documentation.

## Mid/Senior Interview Questions and Answers

### 1. How should engineering resources be evaluated?

**Answer:** Prefer primary documentation, official specifications, production
postmortems, mature books, and high-quality examples over unsourced snippets.

For fast-moving tools, check dates and version compatibility before applying
advice.

### 2. What makes internal documentation useful?

**Answer:** Useful documentation is accurate, searchable, scoped, version-aware,
and connected to real workflows. It explains decisions and trade-offs, not only
commands.

Docs should be maintained as part of the engineering process, especially when
architecture or deployment behavior changes.

### 3. How do you avoid stale documentation?

**Answer:** Assign ownership, review docs with code changes, automate checks
where possible, remove obsolete pages, and include examples that can be tested
or validated.

Stale docs are worse than missing docs when they guide production decisions.
